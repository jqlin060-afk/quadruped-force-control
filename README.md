# 四足机器人力控（VMC）

基于 STM32H723 的四足机器人，用**虚拟模型控制（VMC）**把每条腿当成两根虚拟弹簧，
实现关节层的纯力矩控制。相比位置控制，落地更柔顺、对地面起伏更宽容。

> **当前状态**：平地（地砖）能连续行走，正在解决脚底摩擦不足导致的打滑问题。

---

## 硬件

| 项目 | 规格 |
|---|---|
| 主控 | STM32H723VGT6（Cortex-M7），DM-MC-Board02 板 |
| 电机 | 宇树 GO-M8010-6 × 8（每条腿 2 个），峰值 4.5 N·m |
| 总线 | RS485 半双工，**4 Mbit/s**，USART2 + DMA，DE/RE = PD4 |
| 腿部结构 | 五连杆并联腿，每条腿 2 自由度（矢状面） |
| 连杆尺寸 | 曲柄 L1 = 12.5 cm，连杆 L2 = 26 cm |
| IMU | 板载 BMI088（**尚未启用**） |

**可达腿长**：r ∈ [13.5, 38.5] cm。两端都是退化位形（两曲柄平行），
`det(J) = 0`，实际安全区取 r ∈ [17, 36]。

## 软件架构

```
main.c 主循环（约 300~500 Hz）
│
├─ Leg_ForceBeginCycle()   统计支撑腿数 + 通信看门狗
├─ Leg_ForceUpdate()×4     每条腿算力矩并下发
├─ Motor_SendCmdDMA()      TDMA 收发（发一帧 → 等回复 → 发下一帧）
├─ Motor_PollRx()          解析环形 DMA 缓冲
├─ Motor_CheckOffline()    100 ms 无回复 → 标记离线
├─ Leg_ReadFeedback()×4    正解 → real_point
└─ Leg_ForceObserveAll()   由 tau 反解足端力（只观测）
```

## 核心实现

### 1. 解析 Jacobian

五连杆的足端位置是对两条曲柄的显式函数，求导可以得到解析 Jacobian
（避免数值差分的噪声和开销）。推导见 `Leg_Force.c` 文件头注释。

已用中心差分逐点校验：**两族分支共 1378 个位形，最大相对误差 4×10⁻¹¹**。

### 2. VMC：极坐标下的两根虚拟弹簧

把足端位置换到极坐标 `(r, β)`——因为足端永远在从髋出发的射线上：

```c
r = |p|,  β = atan2(p.y, p.x)
```

- `kr`：沿腿长方向的刚度（腿伸缩）
- `kphi`：绕髋摆角的刚度（前后摆）

广义力：

```c
fr = kr  * (r_d - r) - ff * sin(β)          // 沿腿长
qb = kphi * (β_d - β) - ff * cos(β) * r     // 摆角力矩
qa = fr * rp                                 // rp = dr/dα
```

映射到两个电机（`α = (q1-q2)/2`，`β = (q1+q2)/2`）：

```c
τ1 = (qa + qb) / 2
τ2 = (qa - qb) / 2
```

> **调试恒等式**：`τ1 + τ2 = qa`（管腿长），`τ1 - τ2 = qb`（管摆角）。

### 3. 重力前馈

按**实际支撑腿数**分摊体重：

```c
share = ff_scale * mass * g / n_stance + trim[i]
```

**只在判定触地时施加**。摆动相强制判离地——否则前馈会形成正反馈
（压得越紧 → 力越大 → 越像触地 → 压得更紧），四条腿会卡在"落地"状态
原地踏步。

### 4. 阻尼放在驱动器里

电机驱动器的控制律：

```
τ_out = τ_cmd + kp·(θ_des − θ) + kd·(ω_des − ω)
```

代码里令 `kp = 0`、`ω_des = 0`，得到 `τ_out = τ_cmd − kd·ω`。
阻尼在驱动器的 20 kHz 电流环里算，**没有通信延迟**，比在 MCU 里用
有延迟的反馈做微分稳定得多。

`kd` 按相位分开给（两类腿的等效质量差 8 倍）：

| 相位 | 等效质量 | 临界阻尼 | 采用值 |
|---|---|---|---|
| 摆动 | ~0.8 kg | kd ≈ 0.027 | **0.040** |
| 支撑 | ~6.6 kg | kd ≈ 0.075 | **0.070** |

> 摆动腿除了"腿长"一阶模态，还有"摆角"一阶模态（10.6 Hz）。
> kd 同时作用在两个方向上，而两者的临界阻尼差 2.2 倍——
> 所以用 `swing_boost`（只放大摆动相的腿长刚度）单独补偿腿长方向。

### 5. 安全保护

| 保护 | 触发条件 | 动作 |
|---|---|---|
| 防翻转 | r ∉ [17, 36] 或足端误差 > 8 cm（带迟滞） | 刚度 ×3、撤前馈 |
| 通信看门狗 | 任一条**参与力控**的腿离线 | `g_lf_enable = 0`，整机退回位控 |
| 力矩限幅 | \|τ\| > 8 N·m | 夹住 + 每拍限变 0.4 N·m |
| 单腿开关 | `g_lf_leg_mask` 对应位 = 0 | 该腿单独退回位控 |

## 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| `g_lf_kr` | 1000 N/m | 腿长刚度，1 N/mm（位控是 4.26） |
| `g_lf_kphi` | 80 N·m/rad | 摆角刚度 → 足端前后 1.18 N/mm |
| `g_lf_mass` | 13.4 kg | 前馈用的等效质量（实测总承重 / 9.81） |
| `g_lf_tau_scale` | 6.33 | 转子侧 ↔ 输出轴力矩换算 |
| `g_lf_tau_limit` | 8.0 N·m | 单电机力矩上限（输出侧） |
| `STEP_AX / AY / FREQ` | 4.0 / 6.0 cm / 0.8 Hz | 步幅、抬腿高度、步频 |

### 标定流程

**每条腿的前馈 = 它实际该扛的力**，四条腿才会等高：

```
1. 读四个 g_lf_fz，求和 = ΣF
2. g_lf_mass = ΣF / 9.81
3. trim[i]   = g_lf_fz[i] − ΣF/4
```

> ⚠️ `g_lf_mass_est` **不能**直接填进 `g_lf_mass`——它含关节摩擦，会随姿态漂。

## 踩过的坑

### ① 半双工总线冲突

**现象**：一半电机僵硬（保持位置），一半柔软。固定是偶数号还是奇数号。

**原因**：4 Mbit/s 下，电机回复帧与下一帧命令在总线上碰撞，帧被破坏后
电机直接忽略，一直执行最后一次成功收到的位置帧。

**解决**：改成严格 TDMA——**发一帧，等它的回复，再发下一帧**，用
`DWT->CYCCNT` 计时。之后 `Motor_RxCount[2..9]` 同步递增。

### ② 摆动相触地误判 → 原地踏步

**现象**：四条腿都在前后摆，但机体不前进。

**原因**：重力前馈本身在往下压，形成正反馈：
`力还大 → 判触地 → 给前馈 → 压得更紧 → 力一直大`。

**解决**：摆动相**强制判离地**，不靠力判断。

### ③ 前后刚度太软 → 走不动

**实测**：

| `kphi` | 足端前后刚度 | 现象 |
|---|---|---|
| 25 | 0.37 N/mm | 走偏 |
| 50 | 0.74 N/mm | **原地打滑** |
| **80** | **1.18 N/mm** | **能走**（等于原位控） |

**结论**：腿长方向可以软（柔顺），但**前后方向必须接近位置控制的硬度**，
否则只是把脚在地上搓。

### ④ 腿被压过退化点后翻转卡死

**现象**：脚从最低点直接翻到最高点卡住。

**原因**：`r → 13.5 cm` 时 `det(J) = 0`，腿撑不住任何载荷，被体重压过退化点；
穿过之后曲柄两端重合，足端可沿半径 L2 的整圆任意滑动。

**解决**：防翻转保护（r 越界或误差超限时刚度 ×3、撤前馈）。

### ⑤ 前馈从 0 爬升 → 切换力控时"咔"一声

**现象**：`g_lf_enable` 置 1 的瞬间有明显机械冲击。

**原因**：切换瞬间驱动器 kp 从 1.0 变 0，而前馈还在从 0 慢慢升，
这几十毫秒内腿几乎没有支撑，机体下沉 1~3 cm 再弹回。

**解决**：进力控的第一拍把前馈和力矩**直接就位**（`kf_primed` 标志），
与位控那一拍无缝衔接。

### ⑥ 脚底摩擦不足

**现象**：位控下腿往后蹬时脚在原地滑行；用手压住机体才能走。

**计算**：`kd_stance = 0.075` 在支撑相产生约 18 N/腿 的水平阻力，
两条支撑腿合计 36 N，需要 μ > 0.55 才不打滑；地砖 + 硬塑料脚约 0.2~0.3。

**状态**：待解决（换脚底材料 / 降 `kd_stance`）。

### ⑦ 四条腿机械阻力不一致

需要不同的摆动助力才能抬到同一高度（实测差异达 2.4 倍），
说明关节摩擦/装配有差异。目前用 `g_lf_swing_boost[4]` 逐腿补偿，
但根本解决要机械上润滑/调整。

## 构建

1. 用 STM32CubeMX 打开 `rch7.ioc` 生成代码
2. 用 Keil µVision 5 打开 `MDK-ARM/rch7.uvprojx`
3. 编译下载

或使用 ARMCC 命令行：

```bash
Armcc.exe --c99 --gnu -c --cpu Cortex-M7.fp.dp -O3 \
  -I../Core/Inc -I../Drivers/STM32H7xx_HAL_Driver/Inc -I../Broad \
  -DUSE_HAL_DRIVER -DSTM32H723xx Broad/Leg_Force.c -o Leg_Force.o
```
